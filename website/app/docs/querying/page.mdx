# Querying

`db.Table<T>()` returns a `Table<T>`, which is also a `Query<T>`. Queries are **immutable**:
every method returns a new query, so you can share and extend a base query safely. Nothing runs
until you call a terminal method. Every terminal method has an `...Async` form and a synchronous
form (`ToListAsync()` / `ToList()`).

```csharp
var active = db.Table<Customer>().Where(c => c.Active);           // reusable
var newest = await active.OrderByDescending(c => c.CreatedAt).Take(10).ToListAsync();
var total = await active.CountAsync();
```

## Building a query

| Method | SQL |
|---|---|
| `Where(c => ...)` | `WHERE`; repeated calls are joined with `AND` |
| `Where($"...")` | `WHERE` with a raw, parameterized condition |
| `OrderBy(c => c.X)` / `OrderByDescending` | `ORDER BY`; replaces any previous ordering |
| `ThenBy(c => c.X)` / `ThenByDescending` | adds a secondary sort key |
| `Skip(n)` / `Take(n)` | paging in the dialect's syntax |
| `IgnoreQueryFilters()` | skips the entity's [query filters](/docs/mapping/#query-filters) |
| `Distinct()` | `SELECT DISTINCT` over every mapped column; see [Set operations](#set-operations) |
| `Union(q)` / `Concat(q)` / `Intersect(q)` / `Except(q)` | `UNION`, `UNION ALL`, `INTERSECT`, `EXCEPT`; see [Set operations](#set-operations) |
| `GroupBy(c => c.X)` | `GROUP BY`; see [Grouping](#grouping) |

## Running a query

| Method | Returns |
|---|---|
| `ToListAsync()` / `ToList()` | `List<T>` |
| `StreamAsync()` / `Stream()` | `IAsyncEnumerable<T>` / `IEnumerable<T>` |
| `ToDictionaryAsync(c => key)` / `ToDictionaryAsync(c => key, c => value)` | `Dictionary<TKey, ...>`; keys are computed in .NET, and a duplicate key throws |
| `FirstAsync()` / `FirstAsync(c => ...)` | `T`; throws when there are no rows |
| `FirstOrDefaultAsync()` / `FirstOrDefaultAsync(c => ...)` | `T?` |
| `SingleAsync()` / `SingleAsync(c => ...)` | `T`; throws on zero or several rows |
| `SingleOrDefaultAsync()` / `SingleOrDefaultAsync(c => ...)` | `T?`; throws on several rows |
| `LastAsync()` / `LastOrDefaultAsync()` | the last row in the query's order; needs `OrderBy` |
| `ElementAtAsync(i)` / `ElementAtOrDefaultAsync(i)` | the row at a zero-based position; `ElementAt` throws `ArgumentOutOfRangeException` past the end |
| `CountAsync()` / `CountAsync(c => ...)` | `long` |
| `AnyAsync()` / `AnyAsync(c => ...)` | `bool` |
| `AllAsync(c => ...)` | `bool`; `true` when there are no rows |
| `SumAsync(c => ...)` | the sum; `0` when there are no rows |
| `MinAsync(c => ...)` / `MaxAsync(c => ...)` | the extreme value; `default` (`null` for nullable selectors) when there are no rows |
| `AverageAsync(c => ...)` | `double?`; integers are averaged without truncation; `null` when there are no rows |
| `Select(c => ...)` | a `Projection` with the same terminal methods (see [Projections](#projections)) |
| `ToSql()` / `ToString()` | the SQL, without running it |

`LastAsync` reverses the ordering and reads the first row, so it needs `OrderBy`. After `Skip` or
`Take`, it returns the page's last row. `AllAsync` matches C#: a row where the predicate compares a
`NULL` (such as `p.Score > 3` for a null `int?`) doesn't match.

Aggregates respect `Where`. After `Skip` or `Take`, they apply to that page only, through a subquery:

```csharp
var total = await orders.Where(o => o.Paid).SumAsync(o => o.Amount);
var oldest = await people.MaxAsync(p => (int?)p.Age);             // null for an empty table
var topThree = await scores.OrderByDescending(s => s.Points).Take(3).SumAsync(s => s.Points);
```

## What translates

The translator handles a deliberately focused subset of C#. **Anything else throws
`NotSupportedException` instead of loading the table into memory.** For anything outside the
subset, use `Where($"...")`.

| C# | SQL |
|---|---|
| `==` `!=` `<` `<=` `>` `>=` | `=` `<>` `<` `<=` `>` `>=` |
| `&&` `\|\|` `!` | `AND` `OR` `NOT` |
| `+` `-` `*` `/` `%` | arithmetic |
| `a + b` on strings | `\|\|`, `+` or `CONCAT()` depending on the dialect |
| `x == null`, `x != null` | `IS NULL`, `IS NOT NULL` |
| `x.HasValue`, `x.Value` | `IS NOT NULL`, the column |
| `a ?? b` | `COALESCE(a, b)` |
| `test ? a : b` | `CASE WHEN test THEN a ELSE b END` |
| `(int)x`, `(long)x` on a `double` or `decimal` | truncates toward zero, as C# does (`TRUNC`, `TRUNCATE` or `CAST`) |
| `c.Active` (a `bool` column on its own) | `active = TRUE` (as a parameter) |
| `s.StartsWith(v)`, `s.EndsWith(v)`, `s.Contains(v)` | `LIKE` with `%`, `_`, `[` and `!` escaped |
| `s.ToUpper()`, `s.ToLower()`, `s.Trim()`, `s.TrimStart()`, `s.TrimEnd()` | `UPPER`, `LOWER`, `TRIM`, `LTRIM`, `RTRIM` |
| `s.Length` | `LENGTH`, `LEN` or `CHAR_LENGTH` |
| `s.Substring(i)`, `s.Substring(i, n)` | `SUBSTR(s, i + 1, n)` (`SUBSTRING` in SQL Server) |
| `s.Replace(a, b)` | `REPLACE(s, a, b)` |
| `s.IndexOf(v)` | zero-based position, `-1` when not found (`INSTR`, `STRPOS`, `CHARINDEX`) |
| `s.PadLeft(n)`, `s.PadRight(n, c)` | `LPAD`/`RPAD` (or the dialect's equivalent); never truncates a longer string |
| `string.Compare(a, b)`, `a.CompareTo(b)` | `-1`, `0` or `1` in the database's collation, `NULL` first |
| `string.Concat(...)`, `$"{c.First} {c.Last}"` | concatenation, with `null` as an empty string |
| `n.ToString()` on an integer | `CAST(n AS ...)` |
| `string.IsNullOrEmpty(s)` | `(s IS NULL OR s = '')` |
| `string.IsNullOrWhiteSpace(s)` | `(s IS NULL OR TRIM(s) = '')` |
| `SqlFunctions.Like(s, pattern)` | `s LIKE pattern`, with `%` and `_` as wildcards (not escaped) |
| `d.Year`, `Month`, `Day`, `Hour`, `Minute`, `Second` on `DateTime` (and the date parts of `DateOnly`) | `EXTRACT`, `DATEPART` or `strftime` |
| `d.AddYears(n)` ... `d.AddSeconds(n)` on `DateTime` (`AddYears`, `AddMonths`, `AddDays` on `DateOnly`) | `INTERVAL`, `DATEADD`, `DATE_ADD` or `strftime` modifiers; month ends clamp as in C# |
| `d + timeSpan`, `d - timeSpan` (a `TimeSpan` value) | adds or subtracts its seconds |
| `d.Date` | midnight of the same day |
| `(a - b).TotalDays`, `TotalHours`, `TotalMinutes`, `TotalSeconds` on two `DateTime`s | the difference, with any fraction |
| `Math.Abs(x)`, `Math.Floor(x)`, `Math.Ceiling(x)`, `Math.Sqrt(x)` | `ABS`, `FLOOR`, `CEILING`, `SQRT` |
| `Math.Pow(x, y)` | `POWER(CAST(x AS <float>), y)` |
| `Math.Min(a, b)`, `Math.Max(a, b)` | `CASE WHEN a <= b THEN a ELSE b END` (and `>=`) |
| `list.Contains(c.X)`, `array.Contains(c.X)` | `X IN (@p0, @p1, ...)` |
| `query.Any(o => ...)`, `query.Any()` on another typed query | `EXISTS (SELECT 1 FROM ...)`; see [Subqueries](#subqueries) |
| `query.All(o => ...)` on another typed query | `NOT EXISTS` of a row that fails the predicate |
| `projection.Contains(c.X)` on a one-value projection | `EXISTS (...)` matching the value |
| Captured variables, constants, method calls that don't use the row | evaluated in .NET and sent as parameters |

```csharp
var ids = new[] { 1, 2, 3 };
var minimum = 18;
db.Table<User>().Where(u => ids.Contains(u.Id) && u.Age >= minimum && u.Email != null);
// WHERE ((("id" IN (@p0, @p1, @p2)) AND ("age" >= @p3)) AND ("email" IS NOT NULL))
```

Notes:

- `LIKE` case sensitivity follows the database: case-sensitive in PostgreSQL,
  case-insensitive for ASCII in SQLite, and set by the collation in SQL Server and MySQL.
- Only mapped properties can appear in a query. Computed C# properties throw.
- `Substring` past the end of the string returns the shorter result instead of throwing, as SQL does.
- Date parts of a PostgreSQL `timestamptz` use the session's time zone. MicroORM doesn't translate
  `DateTimeOffset` members, because databases disagree on which offset the parts are in.
- `Math.Round` isn't translated: databases round halves differently from .NET, and from each other.
  Use `Where($"ROUND(price, 2) = {value}")` and pick the behaviour you want.
- SQL Server and MySQL add whole units only, so a fractional amount (`AddDays(1.5)`, or
  `AddHours(x.Minutes / 60.0)`) throws there. Use a smaller unit. On PostgreSQL, adding days to a
  `timestamptz` follows the session's time zone, so a day across a daylight-saving change isn't 24 hours.
- In SQLite, dates are text in Microsoft.Data.Sqlite's format (`yyyy-MM-dd HH:mm:ss.FFFFFFF`). Date
  arithmetic keeps that format, to the millisecond.
- `IndexOf`, `Compare` and `CompareTo` follow the database's collation, like `=`: case-insensitive by
  default in SQL Server and MySQL.
- A concatenation or interpolated string can only contain strings and integers. Other values, and
  placeholders with a format or alignment (`{x.Price:N2}`), throw, because SQL formats them
  differently from .NET.
- Sorting by an expression works too: `OrderBy(u => u.Name.ToLower())`.

## Raw conditions

`Where($"...")` mixes freely with translated predicates:

```csharp
db.Table<User>()
  .Where(u => u.Active)
  .Where($"date_trunc('day', created_at) = {day}")
  .OrderBy(u => u.Name);
```

## Set-based operations

Update or delete every matching row in **one statement**, without loading entities:

```csharp
// UPDATE "users" SET "active" = @p0, "visits" = ("visits" + @p1) WHERE ("last_seen" < @p2)
await db.Table<User>()
    .Where(u => u.LastSeen < cutoff)
    .ExecuteUpdateAsync(s => s
        .Set(u => u.Active, false)
        .SetFrom(u => u.Visits, u => u.Visits + 1));

// DELETE FROM "sessions" WHERE ("expires_at" < @p0)
var removed = await db.Table<Session>().Where(s => s.ExpiresAt < DateTime.UtcNow).ExecuteDeleteAsync();
```

- `Set(column, value)` assigns a value. `SetFrom(column, row => expression)` assigns an expression of the row.
- Both methods return the number of affected rows.
- They reject `OrderBy`, `Skip` and `Take`, because those have no portable meaning in `UPDATE` and `DELETE`.
- **Without `Where`, they affect the whole table.**

`ExecuteUpdateReturningAsync` does the same update and returns the rows as updated, in the same
statement: `RETURNING` in SQLite and PostgreSQL, `OUTPUT INSERTED.*` in SQL Server.

```csharp
// UPDATE "accounts" SET "balance" = ("balance" - @p0) WHERE ("id" = @p1) RETURNING "id", "owner", "balance"
var debited = await db.Table<Account>()
    .Where(a => a.Id == id)
    .ExecuteUpdateReturningAsync(s => s.SetFrom(a => a.Balance, a => a.Balance - amount));
```

MySQL and MariaDB can't return updated rows, so there it throws `NotSupportedException`. On SQL
Server, `OUTPUT` fails on a table with triggers.

## Set operations

`Union`, `Concat`, `Intersect` and `Except` combine two queries of the same entity. `Distinct`
removes duplicate rows. The result is a query like any other: filter, sort, page, project, group or
aggregate it.

```csharp
var people = db.Table<Person>();

// The youngest and the oldest: each side keeps its own ordering and paging.
var ends = await people.OrderBy(p => p.Age).Take(1)
    .Union(people.OrderByDescending(p => p.Age).Take(1))
    .OrderBy(p => p.Name)
    .ToListAsync();
// SELECT ... FROM (SELECT ... FROM (SELECT ... ORDER BY "age" LIMIT 1) AS "people" UNION SELECT ...) AS "people" ORDER BY "name"
```

| Method | SQL | Rows |
|---|---|---|
| `Union(q)` | `UNION` | rows in either query, each distinct row once |
| `Concat(q)` | `UNION ALL` | every row of both queries, duplicates included |
| `Intersect(q)` | `INTERSECT` | distinct rows in both queries |
| `Except(q)` | `EXCEPT` | distinct rows of the first query that the second doesn't return |
| `Distinct()` | `SELECT DISTINCT` | each distinct row once |

- Two rows are the same when every mapped column is equal, `NULL`s included.
- Each side keeps its own filters (including [query filters](/docs/mapping/#query-filters)),
  ordering and paging. The result is read from a derived table under the table's own name, so
  correlated subqueries still refer to it.
- Like SQL, the result has no order until you call `OrderBy`.
- `ExecuteUpdate` and `ExecuteDelete` reject a combined or distinct query. Filter the table instead.
- `Intersect` and `Except` need MySQL 8.0.31 or later.

Projections combine too, even across tables, as long as they select the same type:

```csharp
var everyone = people.Select(p => p.Email).Union(db.Table<Customer>().Select(c => c.Email));
var neverOrdered = people.Select(p => p.Id).Except(orders.Select(o => o.CustomerId));
var lonely = await people.Where(p => neverOrdered.Contains(p.Id)).ToListAsync();
```

## Subqueries

`Any` on another typed query becomes `EXISTS`. Its predicate can use the outer row, so the
subquery is correlated:

```csharp
var orders = db.Table<Order>();

// WHERE EXISTS (SELECT 1 FROM "orders" AS "s0" WHERE ("s0"."customer_id" = "customers"."id"))
var buyers = await db.Table<Customer>().Where(c => orders.Any(o => o.CustomerId == c.Id)).ToListAsync();

// NOT EXISTS, with the subquery's own filter kept inside it.
var bigSpenders = orders.Where(o => o.Amount > 1_000);
var others = await db.Table<Customer>().Where(c => !bigSpenders.Any(o => o.CustomerId == c.Id)).ToListAsync();

// Contains on a projection of one value.
var ordered = orders.Select(o => o.CustomerId);
var withOrders = await db.Table<Customer>().Where(c => ordered.Contains(c.Id)).ToListAsync();
```

- A subquery that has `Where`, `Skip` or `Take` becomes a derived table, so its own filters
  (including [query filters](/docs/mapping/#query-filters)) and paging apply inside it, as in LINQ.
- `Contains` is translated to `EXISTS`, not `IN`, and matches `NULL` the way C# does. With
  `NOT IN`, a single `NULL` in the subquery would make the condition match nothing.
- `All` becomes `NOT EXISTS` of a row that fails the predicate:
  `customers.Where(c => orders.All(o => o.CustomerId != c.Id || o.Paid))`. A customer with no orders
  matches, as in LINQ.
- Subqueries nest. Each level gets its own alias (`s0`, `s1`, ...), so a query can refer to the
  same table it's filtering.
- Subqueries also work in `Select`, where they become `CASE WHEN EXISTS (...) THEN 1 ELSE 0 END`,
  and in `ExecuteUpdate` and `ExecuteDelete`.
- The subquery itself can't depend on the row: correlate in the predicate
  (`orders.Any(o => o.CustomerId == c.Id)`), not with `orders.Where(o => o.CustomerId == c.Id).Any()`.
  Both queries must come from databases with the same dialect.
- A subquery is always translated, never run while the outer query is being built.

## Projections

`Select` chooses what each row returns. Filter, sort and page first, then project:

```csharp
// Anonymous types: each value is aliased with its member name.
var names = await people.Where(p => p.Active).OrderBy(p => p.Name)
    .Select(p => new { p.Id, Upper = p.Name.ToUpper(), Adult = p.Age >= 18 })
    .ToListAsync();
// SELECT "id" AS "Id", UPPER("name") AS "Upper", CASE WHEN ("age" >= @p0) THEN 1 ELSE 0 END AS "Adult" ...

// Records (by constructor parameter name), DTOs (by property name) and single values.
var summaries = await people.Select(p => new PersonSummary(p.Id, p.Name, p.Age)).ToListAsync();
var dtos = await people.Select(p => new NameDto { Id = p.Id, Upper = p.Name.ToUpper() }).ToListAsync();
var emails = await people.Where(p => p.Email != null).Select(p => p.Email).ToListAsync();
```

Each projected value can use anything from [What translates](#what-translates). Conditions
become `CASE WHEN ... THEN 1 ELSE 0 END`, because SQL Server doesn't allow a bare predicate in a
`SELECT` list.

A projection has the terminal methods of a query, and a few of its own:

| Method | What it does |
|---|---|
| `Distinct()` | `SELECT DISTINCT`. After `Skip` or `Take`, the page is taken first, as in LINQ. Any other ordering is dropped, because distinct rows have no order. |
| `Union`, `Concat`, `Intersect`, `Except` | combine with another projection of the same type, from any table; see [Set operations](#set-operations) |
| `CountAsync()` | counts the projected rows (the distinct ones after `Distinct()`) |
| `AnyAsync()` | whether there are any projected rows |
| `ContainsAsync(value)` | whether a one-value projection contains `value` (`null` included) |
| `FirstAsync()`, `SingleOrDefaultAsync()`, `ToDictionaryAsync(...)` | as on a query |

```csharp
var moods = await people.Select(p => p.Mood).Distinct().ToListAsync();
var cities = await customers.Select(c => c.City).Distinct().CountAsync();
```

## Grouping

`GroupBy` groups the rows by a key. Select the key and aggregates from each group:

```csharp
// SELECT "customer_id" AS "CustomerId", COUNT(*) AS "Orders", COALESCE(SUM("amount"), 0) AS "Total"
// FROM "orders" WHERE ("paid" = @p0) GROUP BY "customer_id" HAVING (COUNT(*) > @p1)
// ORDER BY COALESCE(SUM("amount"), 0) DESC LIMIT 10
var top = await db.Table<Order>()
    .Where(o => o.Paid)
    .GroupBy(o => o.CustomerId)
    .Having(g => g.Count() > 1)
    .OrderByDescending(g => g.Sum(o => o.Amount))
    .Take(10)
    .Select(g => new { CustomerId = g.Key, Orders = g.Count(), Total = g.Sum(o => o.Amount) })
    .ToListAsync();
```

- `Where` before `GroupBy` filters rows. `Having` after it filters groups.
- Sort and page groups with `OrderBy`, `ThenBy`, `Skip` and `Take` before `Select`.
- Aggregates over a group: `g.Count()`, `g.Count(x => ...)`, `g.LongCount()`, `g.Sum(x => ...)`
  (zero when every value is `NULL`, as in LINQ), `g.Min(x => ...)`, `g.Max(x => ...)` and
  `g.Average(x => ...)` (integers averaged as floating point; decimals stay exact).
- A composite key is an anonymous type: `GroupBy(p => new { p.Country, p.City })`, then select
  `g.Key.Country` and `g.Key.City`. `OrderBy(g => g.Key)` sorts by each part.
- A key can be computed, such as `GroupBy(p => p.CreatedAt.Year)`. Computed keys, and sources
  with `Skip` or `Take`, are grouped through a derived table, so the key is computed once and
  the page is taken before grouping, as in LINQ.
- `CountAsync()` on a grouped query counts the groups.
- Subqueries aren't supported inside grouped queries, and whole groups can't be selected
  (`Select(g => g)`). Select the key and aggregates instead.

For joins and other shapes a single table can't express, write the SQL and materialize into a
record (see also [Joins and result sets](/docs/joins-and-result-sets/)):

```csharp
public record CustomerTotal(int Id, string Name, decimal Spend);

var totals = await db.QueryAsync<CustomerTotal>($"""
    SELECT c.id, c.name, SUM(o.amount) AS spend
    FROM customer c JOIN orders o ON o.customer_id = c.id
    WHERE o.placed_at >= {since}
    GROUP BY c.id, c.name
    """);
```
